# SVIn ZED 数据录制与前端 VIO 偏移排查清单

本文用于下一次录制 ZED 双目 + IMU 数据包时逐项检查，目标是减少 SVIn 前端 VIO 黄色轨迹 `/okvis_path` 的偏移、漂移、尺度错误和发散。

## 一、当前问题结论

本次 20260610 数据可以运行，但 RViz 中黄色轨迹与真实实验轨迹差别明显。已观察到的主要问题：

- `/okvis_path` 黄色轨迹是 OKVIS/SVIn 前端 VIO 实时估计，不是参考轨迹。
- 运行时出现过 `Received image from the past`、`Dropping frame`、`Frame delayed`。
- 原始图像为 `bgra8 1920x1080`，单帧约 8.3 MB，处理负载较重。
- 轨迹未发散到公里级，但结果范围偏小，说明前端尺度、时间同步或外参仍未完全适配。

优先级判断：

1. 先保证数据流稳定、同步、轻量。
2. 再做同一套设备、同一分辨率下的相机-IMU联合标定。
3. 最后再微调 SVIn 参数。

## 二、录制前检查

### 1. 相机参数

建议优先使用：

- 分辨率：`HD720 1280x720`
- 帧率：`15 Hz`
- 图像编码：优先 `mono8` 或 `bgr8`，避免长期使用 `bgra8 1920x1080`
- ZED positional tracking：关闭
- 深度、点云、目标检测等无关功能：关闭

检查项：

- [ ] 左右目图像清晰。
- [ ] 图像不过暗、不过曝。
- [ ] 不使用太高分辨率导致 CPU/GPU 压力过大。
- [ ] 录制端帧率和 SVIn 配置里的 `camera_rate` 一致或接近。
- [ ] 如果修改了分辨率，已经重新做双目标定。

### 2. IMU 参数

检查项：

- [ ] IMU 话题已录制。
- [ ] 角速度单位为 `rad/s`。
- [ ] 加速度单位为 `m/s^2`。
- [ ] IMU 频率稳定，最好大于 100 Hz。
- [ ] IMU 时间戳单调递增。
- [ ] 设备静止时加速度模长接近 `9.81 m/s^2`。

### 3. 标定文件

必须保证这些内容来自同一套设备、同一分辨率、同一安装状态：

- [ ] 左右相机内参。
- [ ] 左右相机外参。
- [ ] 相机到 IMU 外参。
- [ ] IMU 噪声参数。
- [ ] camera-IMU 时间偏移。

不要长期混用：

- Kalibr 双目标定结果。
- ZED SDK 内置左相机到 IMU TF。
- 不同日期、不同分辨率、不同安装状态的标定文件。

## 三、录制动作要求

### 1. 开始阶段

每个导航数据包开头建议：

- [ ] 设备完全静止 10 到 20 秒。
- [ ] 静止时不要碰设备。
- [ ] 确认左右相机都能看到有纹理的环境。
- [ ] 不要一开始就快速转动或平移。

原因：

SVIn/OKVIS 前端需要稳定初始化。初始化阶段如果 IMU 偏置、重力方向、视觉特征都不稳定，后面黄色轨迹会一直带着偏差。

### 2. 运动阶段

推荐动作：

- [ ] 先慢速平移，再慢速转弯。
- [ ] 避免突然快速旋转。
- [ ] 避免剧烈抖动。
- [ ] 避免长时间只旋转不平移。
- [ ] 避免长时间对着白墙、地面、天空或强反光物体。
- [ ] 让左右相机始终看到足够纹理。

建议轨迹：

- 小范围测试：走一个 1 m 到 2 m 的矩形。
- 中等测试：走一个 3 m 到 5 m 的闭环。
- 每次记录真实路径尺寸，比如长、宽、起终点是否重合。

### 3. 结束阶段

- [ ] 结束前静止 5 到 10 秒。
- [ ] 不要刚停下就立刻停止录包。
- [ ] 记录本次真实运动描述，例如“约 2 m x 1 m 矩形，最后回到起点”。

## 五、录制后快速检查

### 1. 查看 bag 基本信息

```bash
ros2 bag info /path/to/bag
```

记录：

- [ ] bag 总时长。
- [ ] 左目图像数量。
- [ ] 右目图像数量。
- [ ] IMU 数量。
- [ ] 图像实际频率。
- [ ] IMU 实际频率。

判断：

- 左右目数量应该基本一致。
- IMU 数量应该远大于图像数量。
- 图像频率应接近配置里的 `camera_rate`。

### 2. 检查图像话题频率

```bash
source /opt/ros/humble/setup.bash
ros2 bag play /path/to/bag --clock
```

另开终端：

```bash
source /opt/ros/humble/setup.bash
ros2 topic hz /zed/zed_node/left/color/raw/image --window 30
ros2 topic hz /zed/zed_node/right/color/raw/image --window 30
ros2 topic hz /zed/zed_node/imu/data_raw --window 100
```

检查项：

- [ ] 左目频率稳定。
- [ ] 右目频率稳定。
- [ ] 左右目频率接近。
- [ ] IMU 频率稳定。

### 3. 检查左右目时间差

目标：

- 左右目 header stamp 最好完全相同。
- 允许少量误差，最好小于 5 ms。
- 大量超过 20 ms 时，SVIn 前端很容易不稳。

### 4. 检查是否有时间倒退

如果运行 SVIn 时出现：

```text
Received image from the past
Dropping frame
Frame delayed
```

说明需要优先处理数据顺序和同步问题。

处理建议：

- [ ] 不直接跑原始大分辨率 `bgra8` bag。
- [ ] 先生成 SVIn 专用预处理 bag。
- [ ] 预处理时按 header 时间排序。
- [ ] 左右图像使用共同时间戳。
- [ ] 将图像转成 `mono8` 或 `bgr8`。
- [ ] 将 1920x1080 缩放到 960x540 或直接录制 1280x720。

## 六、SVIn 配置检查

### 1. `camera_rate`

配置位置：

```text
/home/zhuchao/svin_ws/src/SVIn/config/config_zed_stereo_20260610.yaml
```

检查：

- [ ] 实测 14 Hz 左右，`camera_rate` 设为 `14`。
- [ ] 实测 15 Hz 左右，`camera_rate` 设为 `15`。
- [ ] 实测 30 Hz 左右，才设为 `30`。

错误影响：

- `camera_rate` 过高会让双目同步容忍度变小，容易丢帧。
- `camera_rate` 和真实帧率差太多，会让前端处理节奏不稳定。

### 2. `resizeFactor`

说明：

- `resizeFactor: 0.5` 表示图像进入前端前缩小为原来一半。
- 1920x1080 加 0.5 后实际处理为 960x540。
- 内参会随缩放自动调整，不需要手动改 fx、fy、cx、cy。

检查：

- [ ] 原始 `image_dimension` 和标定分辨率一致。
- [ ] `resizeFactor` 只用于降低处理负载。
- [ ] 不把缩放后的分辨率误填成原始标定分辨率。

### 3. `imageDelay`

检查：

- [ ] 没有可靠 camera-IMU 时间偏移时，先使用 `0.0`。
- [ ] 如果 Kalibr 得到 `timeshift_cam_imu`，再有依据地修改。
- [ ] 不靠肉眼轨迹随意调大调小。

错误影响：

时间偏移错误会导致转弯、加减速时轨迹偏移明显。

### 4. `T_SC` 相机-IMU外参

检查：

- [ ] 外参来自同一套设备。
- [ ] 外参方向已经通过实验验证。
- [ ] 不随意取逆。

当前经验：

20260610 中测试过 inverse `T_SC`，结果严重发散，不可用。

## 七、黄色轨迹异常对应处理

### 现象 1：黄色轨迹整体方向不对

优先检查：

- [ ] 相机-IMU外参方向。
- [ ] IMU 坐标系定义。
- [ ] 左右相机是否接反。
- [ ] 图像是否被错误旋转或镜像。

### 现象 2：黄色轨迹尺度明显太小

优先检查：

- [ ] 双目 baseline 是否正确。
- [ ] 相机内参是否对应当前分辨率。
- [ ] `resizeFactor` 是否和内参处理逻辑一致。
- [ ] IMU 噪声参数是否不合理。
- [ ] camera-IMU 时间偏移是否未标定。

### 现象 3：黄色轨迹突然跳变

优先检查：

- [ ] 是否出现 `Dropping frame`。
- [ ] 是否出现 `Received image from the past`。
- [ ] 是否有图像或 IMU 断流。
- [ ] 是否运动过快或图像模糊。

### 现象 4：黄色轨迹快速发散到很远

优先检查：

- [ ] `T_SC` 是否方向错误。
- [ ] IMU 单位是否错误。
- [ ] 重力方向是否初始化失败。
- [ ] 左右目同步是否失败。
- [ ] 相机内参是否不是当前分辨率的标定。

### 现象 5：bus 数据集正常，自采数据不正常

说明：

算法本身大概率能运行，主要差异在数据自洽性。

优先排查：

- [ ] 自采数据时间戳。
- [ ] 自采数据双目同步。
- [ ] 自采数据图像负载。
- [ ] 自采数据相机-IMU外参。
- [ ] 自采数据 camera-IMU 时间偏移。

## 八、分辨率、特征点和轨迹精度折中

### 1. 分辨率降低是否会影响特征点

会影响，但不是分辨率越高轨迹越准。

VIO 更需要：

- 稳定帧率。
- 稳定时间戳。
- 左右目同步。
- 足够但不过量的特征点。
- 准确相机-IMU外参。
- 准确 camera-IMU 时间偏移。

如果高分辨率导致：

```text
Dropping frame
Received image from the past
Frame delayed
```

那么高分辨率会让轨迹更差。

### 2. 推荐折中方案

优先测试：

- [ ] `1280x720 @ 15Hz`，`resizeFactor: 1.0`
- [ ] 图像编码用 `mono8` 或 `bgr8`
- [ ] SVIn 配置 `camera_rate: 15`

备选方案：

- [ ] `1920x1080 @ 15Hz`，`resizeFactor: 0.5`，实际处理约 `960x540`
- [ ] `1280x720 @ 30Hz`，仅在电脑可以稳定实时处理时使用
- [ ] `1280x720 @ 15Hz`，`resizeFactor: 0.75`，实际处理约 `960x540`

不建议一开始使用：

- [ ] `1920x1080 bgra8 @ 30Hz`
- [ ] 高分辨率同时开启深度、点云、定位、目标检测等额外模块

### 3. 如何判断分辨率是否足够

判断标准：

- [ ] SVIn 不再出现大量丢帧。
- [ ] 图像中角点/纹理丰富。
- [ ] 黄色轨迹连续，没有频繁跳变。
- [ ] 小矩形测试的尺度接近真实尺寸。
- [ ] 起终点闭合误差明显变小。

如果特征点不足，优先改善环境，而不是盲目升分辨率：

- 增加光照。
- 降低运动速度。
- 避免纯白墙、玻璃、反光地面。
- 在实验场地增加纹理纸、AprilTag、棋盘格或明显边缘物体。
- 避免图像过曝和运动模糊。

### 4. 关于“完美准确轨迹”

纯 VIO 很难做到完美准确。可达到的目标应是：

- 短距离尺度接近真实路径。
- 方向正确。
- 局部轨迹平滑。
- 闭环后起终点误差较小。
- 多次重复实验结果一致。

要接近这个目标，需要同时满足：

```text
干净同步的数据流
+ 同一分辨率下的双目标定
+ 同一设备安装状态下的 camera-IMU 联合标定
+ 正确 camera-IMU 时间偏移
+ 稳定初始化
+ 有纹理、慢运动
+ 回环/pose graph 优化
```

## 九、Kalibr 外参与 ZED SDK 外参差异大的处理思路

### 1. 先不要直接混用两套外参

如果每次用 Kalibr 标定出的相机-IMU 外参与 ZED SDK 输出外参相差较大，不要直接把：

- Kalibr 双目标定
- ZED SDK 左相机到 IMU TF
- 某一次导航 bag 中的时间戳

混在同一个 SVIn 配置里长期使用。

这样很容易造成：

- 黄色轨迹方向偏。
- 尺度异常。
- 转弯时轨迹横向漂移。
- 初始化后快速发散。

### 2. 首先确认比较的是同一个变换

Kalibr 和 ZED SDK 输出的外参可能表达的不是同一个方向。

必须确认：

- [ ] Kalibr 输出的是 `T_cam_imu`、`T_imu_cam`、`T_cn_cnm1` 还是其他命名。
- [ ] ZED SDK 输出的是 left camera frame 到 imu link，还是 imu link 到 left camera frame。
- [ ] SVIn 配置里的 `T_SC` 到底期望的是 camera-to-IMU 还是 IMU-to-camera。
- [ ] 比较前是否需要取逆。
- [ ] 比较前是否需要从 camera frame 转到 optical frame。

经验提醒：

20260610 中测试过简单取逆 `T_SC`，结果严重发散，所以不能只靠变量名判断，必须用实际运行验证。

### 3. 确认坐标系是否一致

ZED/ROS 常见坐标系：

```text
camera_link:
  x forward
  y left
  z up

camera_optical_frame:
  x right
  y down
  z forward
```

SVIn/OKVIS 通常处理的是相机光学坐标系。比较外参前检查：

- [ ] Kalibr 使用的是图像光学坐标系。
- [ ] ZED SDK TF 是否是 `zed_left_camera_frame`，而不是 `zed_left_camera_optical_frame`。
- [ ] 是否需要 `camera_frame -> optical_frame` 的固定旋转。
- [ ] 左相机、右相机没有接反。
- [ ] 图像没有被旋转、镜像或裁剪后仍使用旧内参。

如果没有转换到同一坐标系，两个外参看起来会差很多，但并不代表某一个一定错。

### 4. 确认分辨率和相机模型一致

每次换分辨率都应重新标定。

检查项：

- [ ] Kalibr 标定 bag 的分辨率和导航 bag 一致。
- [ ] SVIn 配置里的 `image_dimension` 与标定分辨率一致。
- [ ] `focal_length`、`principal_point` 来自同一分辨率。
- [ ] 畸变模型与 Kalibr 输出一致。
- [ ] 如果图像被裁剪或 binning，不能直接使用原始内参。

`resizeFactor` 只表示 SVIn 内部缩放处理图像，不等于标定分辨率改变。配置里仍应填写原始标定分辨率对应的内参。

### 5. 确认 Kalibr 标定数据质量

Kalibr 标定外参不稳定时，常见原因是采集动作不合格。

采集 camera-IMU 标定 bag 时：

- [ ] 标定板尺寸、格子数量、tag 尺寸填写正确。
- [ ] 标定板固定不动。
- [ ] 相机完整看到标定板，覆盖图像中心和四角。
- [ ] 有平移，也有绕 x/y/z 轴的旋转。
- [ ] 不要只在一个平面内小幅晃动。
- [ ] 运动不要太快，避免运动模糊。
- [ ] 光照稳定。
- [ ] 采集时长足够，建议 1 到 3 分钟。
- [ ] 开头和结尾可以短暂静止。
- [ ] 左右相机都能稳定检测到 AprilGrid。

如果 Kalibr 多次标定结果差异很大，优先认为标定数据质量或时间同步存在问题。

### 6. 确认 camera-IMU 时间偏移

相机-IMU 时间偏移会直接影响外参估计。

检查项：

- [ ] Kalibr 是否开启并估计了 `timeshift_cam_imu`。
- [ ] 多次标定得到的 time shift 是否接近。
- [ ] time shift 是否被正确填入 SVIn 的 `imageDelay` 或对应字段。
- [ ] bag 中相机和 IMU header 时间是否来自同一时钟。
- [ ] 录包时是否出现图像或 IMU 断流。

如果时间偏移不稳定，外参也可能被 Kalibr “补偿”成错误姿态。

### 7. 如何判断 Kalibr 和 ZED SDK 该信谁

建议不要抽象判断，直接做 A/B 实验。

准备三套配置：

- [ ] A：完全使用 Kalibr 输出的双目 + camera-IMU 外参 + time shift。
- [ ] B：使用 ZED SDK 左相机-IMU 外参 + Kalibr 双目内外参。
- [ ] C：当前 SVIn 最佳基线配置。

用同一个短测试 bag 运行：

```text
HD720 15Hz
开头静止 15 秒
走 1 m x 1 m 或 2 m x 1 m 矩形
回到起点
结尾静止 10 秒
```

比较指标：

- [ ] 是否初始化成功。
- [ ] 是否出现大量丢帧。
- [ ] 轨迹方向是否正确。
- [ ] 轨迹尺度是否接近真实矩形。
- [ ] 起终点闭合误差是否更小。
- [ ] 多次运行是否稳定。

哪一套在真实短轨迹上表现稳定，就先作为工程基线。

### 8. 推荐解决路线

建议路线：

1. 固定 ZED 安装和 IMU 安装，之后不要移动相机和 IMU 的相对位置。
2. 固定录制分辨率，例如 `HD720 1280x720`。
3. 录制高质量 Kalibr camera-IMU 标定 bag。
4. 用 Kalibr 得到完整同源参数：双目内参、双目外参、相机-IMU外参、time shift。
5. 把外参统一转换到 SVIn 期望坐标系。
6. 用短矩形导航 bag 做 A/B 验证。
7. 记录最优配置，并只在同一硬件安装和同一分辨率下使用。
8. 如果更换分辨率、移动相机、拆装设备，重新标定。

## 十、推荐的下一步标准流程

### Step 1：录一包短测试数据

目标输出：

- 双目内参。
- 双目外参。
- IMU 到相机外参。
- camera-IMU 时间偏移。

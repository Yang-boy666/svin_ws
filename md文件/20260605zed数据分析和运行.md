## 停车后轨迹继续前移的分析

用户观察：

```text
小车运动了一段距离后停下，但 RViz 里的轨迹还继续向前移动，随后轨迹明显发散。
```

针对该现象进一步统计 bag 时间戳，结论如下。

### 1. 图像在停车后段出现明显断流

左目图像 header stamp 大间隔：

```text
/zed/zed_node/left/color/raw/image
gap index 2174->2175 header 1.873s at rel 145.576-147.449s
gap index 2224->2225 header 0.581s at rel 150.678-151.259s
gap index 2293->2294 header 0.221s at rel 155.746-155.967s
```

右目图像 header stamp 大间隔：

```text
/zed/zed_node/right/color/raw/image
gap index 2174->2175 header 1.873s at rel 145.576-147.450s
gap index 2224->2225 header 0.581s at rel 150.678-151.259s
gap index 2293->2294 header 0.221s at rel 155.746-155.968s
```

这说明左右目在同一时间段一起断流，不是单目同步小误差，而是图像流整体停顿。

### 2. IMU 判断停车区间

用 2 秒窗口统计 IMU 角速度模长和加速度模长标准差，低运动窗口如下：

```text
static-like intervals by gyro_mean<0.025 rad/s and accel_norm_std<0.035:
0.0 - 3.0 s
7.0 - 12.0 s
115.0 - 124.0 s
144.0 - 165.0 s
```

其中 `144.0 - 165.0s` 很可能就是小车后段停车时间。图像最大断流 `145.576 - 147.449s` 正好落在停车后段。

### 3. 为什么停车后轨迹还向前走

VIO 的状态里包含位置、姿态、速度、IMU bias。车辆刚停下时，如果视觉帧断流或延迟，优化器无法及时用视觉重投影约束把速度压回 0；此时系统会继续用 IMU 传播状态。只要前一刻估计速度还有残留，或者加速度 bias/重力方向有一点误差，位置就会继续往前积分。

这就是现象链条：

```text
车已经停下
-> 图像流在 145.6s 附近断了约 1.87s
-> SVIn 收不到稳定视觉校正
-> IMU 传播继续带着旧速度/偏置往前推
-> RViz 轨迹继续前移
-> 后面再来图像时状态已经偏了，容易 Tracking failure 或明显发散
```

### 4. 为什么 bus 官方数据集效果更好

官方 bus 数据集更稳定的核心不是“场景一定更好看”，而是数据更自洽：

```text
图像没有 1 秒级断流
相机频率和配置接近
IMU 频率和配置接近
相机-IMU 外参、时间偏移、噪声参数来自同一套数据
```

20260605 这包数据目前暴露的问题：

```text
图像后段有 1.87s、0.58s、0.22s 断流
运行时出现 Received image from the past / Frame delayed / Dropping frame
后段出现 Tracking failure. Number of 3d2d-matches: 0
当前 T_SC 沿用 20260610 配置，未确认是否适配 20260605 采集状态
```

### 5. 当前优先级判断

优先级最高的是先处理数据流：

```text
1. 重新录制或预处理 bag，避免图像 1 秒级断流。
2. 确认左右目 header stamp 同步并按 header 时间严格排序。
3. 确认图像和 IMU 时间偏移，不要长期用 imageDelay: 0.0 硬跑。
4. 用 20260605 对应采集状态重新确认 T_SC。
5. 最后再调 detection threshold、maxNoKeypoints、IMU 噪声等参数。
```
